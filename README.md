# vetKlinika

Веб-приложение для ветеринарной клиники: учёт клиентов, питомцев, приёмов и медицинских документов. Backend на Go с REST API и SQLite, фронтенд на HTML, JavaScript и Bootstrap.

## Возможности

- **Клиенты (владельцы):** создание, список, поиск по ФИО, карточка, редактирование, удаление.
- **Питомцы:** привязка к владельцу, кличка, вес, возраст, вид животного, аллергии. Возраст хранится на дату записи и пересчитывается при каждом чтении.
- **Справочник видов животных:** новый вид создаётся автоматически при редактировании питомца.
- **Приёмы:** дата, анамнез, диагноз, лечение и рекомендации; история приёмов питомца.
- **Документы:** файлы (анализы, снимки) хранятся в БД и привязываются к питомцу и приёму.
- **Логирование:** каждый запрос пишется в JSON-лог (logrus) с методом, путём и адресом клиента.
- При запуске приложение само открывает браузер.

## Стек

- Go, стандартный `net/http`
- SQLite через `modernc.org/sqlite` (чистый Go, без CGO), представление `pets_with_types`, индексы по кличке и дате приёма
- `logrus` для логов, `cleanenv` для конфигурации из YAML
- HTML, JavaScript, Bootstrap

## Структура

```text
backend/
  cmd/main.go            точка входа: конфиг, логгер, БД, сервер
  internal/handlers/     HTTP-обработчики: persons, pets, types, appointments, documents
  internal/middleware/   цепочка middleware, логгер и хранилище в контексте запроса
  internal/server/       маршруты API и раздача статики
  internal/service/      конфигурация, логгер, работа с датами и возрастом
  internal/storage/      схема БД и запросы
frontend/                страницы: клиенты, карточки клиента и питомца, приёмы
config.yaml              порт, путь к БД и к логам
```

## Запуск

1. Проверьте `config.yaml`: путь к БД должен существовать на вашей машине.

   ```yaml
   db_path: "./db/storage.db"
   port: 8080
   logger_path: "./logs/logs.log"
   ```

2. Запустите из корня репозитория (пути к `config.yaml` и `frontend/` относительные):

   ```bash
   go run ./backend/cmd
   ```

Таблицы создаются автоматически при первом запуске, браузер откроется на `http://localhost:8080`.

## API

| Ресурс | Методы | Параметры GET |
|---|---|---|
| `/api/persons` | GET, POST, PUT, DELETE | `id`, `name` (поиск по ФИО) |
| `/api/pets` | GET, POST, PUT, DELETE | `id`, `ownerId`; при POST владелец передаётся в `ownerId` |
| `/api/types` | GET, POST | `id`, `name` |
| `/api/appointments` | GET, POST, PUT | `id`, `petId` |
| `/api/documents` | GET, POST, DELETE | `id`, `petId`, `appointmentId` |

## Страницы

| Путь | Что на ней |
|---|---|
| `/` | список клиентов и поиск |
| `/person/create/` | новый клиент |
| `/person/` | карточка клиента и его питомцы |
| `/pets/` | карточка питомца |
| `/visit/create/` | новый приём |
| `/visit/` | карточка приёма |

## Тесты

```bash
go test ./...
```

Тесты покрывают хранилище (каждый тест работает с чистой SQLite-БД во временной папке), HTTP-обработчики (через `httptest`) и сервисные функции. CI запускает их на каждый push.
